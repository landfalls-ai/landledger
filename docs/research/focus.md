# FOCUS 1.4: the columns Landledger keeps

FOCUS (the FinOps Open Cost and Usage Specification) names the columns of a cost and usage dataset. Landledger stores
its `cost_records` in FOCUS columns so a finance analyst, Datarails or any FinOps tool reads them without a mapping, and
so a cloud bill exported as FOCUS later lands in the same table.

Source: `upstream/focus-spec` at tag **v1.4** (`f1eeb30`, released 2026-06-04, the latest ratified version; `v1.5-cr`
of 2026-11-02 is a candidate release and is not used), pinned by `scripts/fetch-upstream.sh`. Licence: Creative Commons
Attribution 4.0 for the documents (`upstream/focus-spec/license.md:3`), patent policy W3C mode
(`upstream/focus-spec/license.md:29`). Paths below are relative to `upstream/focus-spec/specification/`; the cost and
usage columns are in `datasets/cost_and_usage/columns/`. [docs] does not apply here: the specification is the source.

## Summary

- Landledger is an **internal showback ledger**, not a provider's billing export. It keeps FOCUS names and meanings,
  follows FOCUS's **ledger correction style** exactly, and departs from FOCUS in one documented place: on an
  `estimated` row, `BilledCost` is 0 and `EffectiveCost` carries the estimate (§2).
- 45 of the 65 cost-and-usage columns are kept, including the 1.3 split-cost-allocation columns, which describe cluster
  cost split into workloads plus an unallocated (idle) portion exactly (§3).
- Custom columns use FOCUS's `x_` prefix and Pascal case (`attributes/custom_column_handling.md:23`-`:24`).
- AI tokens are a FOCUS unit (`Token`, `attributes/unit_format.md:121`); prices per million tokens are expressed as the
  pricing unit `1000000 Tokens` (`unit_format.md:28`).
- FOCUS 1.4 adds the **Billing Period** dataset (`Open` / `Closed`) and **Invoice Detail**: Landledger's `periods` and,
  in wave 3, its `invoices` follow them.

## 1. What changed in 1.4 that matters here

From `upstream/focus-spec/CHANGELOG.md:7`-`:208`:

- **Correction Handling** (new attribute): three styles, Replacement, Delta and **Ledger**, the last being "explicit
  reversals and re-entries" appended, "full inherent auditability" (`attributes/correction_handling.md:21`-`:27`,
  `:47`-`:53`). This is Landledger's append-only rule, in FOCUS's words.
- **Custom Column Handling** (new attribute, `custom_column_handling.md:54`-`:56`), replacing the old `ColumnHandling`.
- **Billing Period** and **Invoice Detail** datasets, and the `InvoiceDetailId` column, for invoice reconciliation.
- **Revised `BilledCost` and `EffectiveCost`** requirements (below).
- `ProviderName` and `PublisherName` are **removed**; use `ServiceProviderName`, `HostProviderName` and
  `InvoiceIssuerName` (`CHANGELOG.md:32`, `:207`-`:208`).

## 2. Estimated against invoiced: where the money goes

FOCUS 1.4 is strict about `BilledCost`:

- "BilledCost MUST reflect amounts as invoiced by the InvoiceIssuerName, not estimated or inferred values"
  (`billedcost.md:20`), and "MUST be 0 for charges generated by entities that are not responsible or authorized for
  invoicing" (`billedcost.md:21`).
- `EffectiveCost` "MUST equal BilledCost when ChargeCategory is "Usage" and the charge is not covered"
  (`effectivecost.md:18`).
- `ListCost` and `ContractedCost` are unit price × `PricingQuantity` (`listcost.md:16`, `contractedcost.md:16`).

A notional cluster cost or a token estimate is exactly "estimated or inferred". So Landledger fills the four cost
columns like this:

| Column | `estimated` row (usage × rate card) | `invoiced` row (from a provider's invoice, wave 3) |
|---|---|---|
| `ListCost` | `ListUnitPrice` × `PricingQuantity` (provider list price; for the cluster, the rate card) | as the provider reports it |
| `ContractedCost` | `ContractedUnitPrice` × `PricingQuantity` (the approved rate card) | as the provider reports it |
| `BilledCost` | **0** (nothing was invoiced; `billedcost.md:20`-`:21`) | the invoiced amount |
| `EffectiveCost` | **= `ContractedCost`**: the figure showback, budgets and Explore use | = `BilledCost` for usage (`effectivecost.md:18`) |

The departure is `EffectiveCost ≠ BilledCost` on estimated usage rows. It is deliberate: summing `BilledCost` gives
exactly the money that was invoiced and nothing notional, which is principle 2 ("notional cluster cost never goes to the
books as actuals") enforced by the data shape; summing `EffectiveCost` gives the management view. `x_Basis` says which
rule a row follows, and `libs/focus`'s conformance check applies the FOCUS rules in full to `invoiced` rows and the
documented exception to `estimated` ones. A FOCUS export for outside tools (not planned before wave 5) would mark the
estimated rows or leave them out.

## 3. The columns Landledger keeps

Type, feature level and nullability are FOCUS's (each column file's *Content Constraints* table). "Use" is how
Landledger fills it.

### Money, quantity and price

| Column | Type | Level | Null | Meaning | Use |
|---|---|---|---|---|---|
| `BilledCost` | Decimal | Mandatory | no | Invoiced amount in `BillingCurrency` | §2 |
| `EffectiveCost` | Decimal | Mandatory | no | Amortized cost after discounts | §2; the figure the console shows |
| `ListCost` | Decimal | Mandatory | no | List price × pricing quantity | §2 |
| `ContractedCost` | Decimal | Mandatory | no | Contracted price × pricing quantity | §2 |
| `ListUnitPrice` | Decimal | Conditional | yes | Public price per pricing unit | AI: the provider's list price; cluster: the rate card |
| `ContractedUnitPrice` | Decimal | Conditional | yes | Agreed price per pricing unit | The approved rate card's price |
| `PricingQuantity` | Decimal | Mandatory | yes | Quantity in `PricingUnit` | e.g. tokens ÷ 1,000,000; GB-hours ÷ 730 |
| `PricingUnit` | String | Mandatory | yes | Unit the price is per | `1000000 Tokens`, `Core-Hours`, `GiB-Hours`, `GB-Months`, `GB` |
| `ConsumedQuantity` | Decimal | Conditional | yes | What was used, in `ConsumedUnit` | tokens; core-hours; GiB-hours; GB-hours; GB |
| `ConsumedUnit` | String | Conditional | yes | Unit of use | `Tokens`, `Core-Hours`, `GiB-Hours`, `GB-Hours`, `GB` |
| `BillingCurrency` | String | Mandatory | no | ISO 4217 code of the bill | `USD` (decision 6) |

Rules that bind: `ConsumedQuantity` must be set on Usage rows that aren't corrections (`consumedquantity.md:14`-`:15`);
cost = unit price × `PricingQuantity` whenever both are set (`pricingquantity.md:16`); unit strings follow Unit Format
(`unit_format.md:20`-`:28`): compound units with a hyphen (`GB-Hours`), a unit quantity as a leading integer
(`1000 Tokens`); data sizes distinguish `GB` (10⁹) from `GiB` (2³⁰) (`unit_format.md:82`, `:88`), so memory is priced in
GiB-hours and storage and network in GB, as decision 3 states them.

### When, and which period

| Column | Type | Level | Null | Meaning | Use |
|---|---|---|---|---|---|
| `ChargePeriodStart`, `ChargePeriodEnd` | Date/Time | Mandatory | no | Inclusive start, exclusive end of the charge | The UTC day of the usage (`2026-11-13T00:00:00Z` to `2026-11-14T00:00:00Z`) |
| `BillingPeriodStart`, `BillingPeriodEnd` | Date/Time | Mandatory | no | The billing period the row belongs to | The Landledger month it is booked in: the usage month, or the open month for a correction to a locked one (§6) |

All date/times are UTC, `YYYY-MM-DDTHH:mm:ssZ` (`attributes/datetime_format.md:9`-`:15`). A day is a UTC day; Landflow's
`day` field is in the instance's time zone (`landflow-clickland/apps/web/src/lib/shared/brain.ts:89`-`:90`), so
Landledger buckets AI calls by their UTC timestamp, never by that field.

### Split cost allocation: cluster cost, workloads and idle

FOCUS 1.3 added the data generator's own split of one charge into finer ones, with an **unallocated portion** (e.g.
unused capacity): the split rows' summable metrics must add up to the origin charge
(`attributes/data_generator_calculated_split_cost_allocation_handling.md:3`, `:9`-`:11`); the unallocated portion has a
null `AllocatedResourceId` (`allocatedresourceid.md:13`-`:14`).

That is OpenCost's idle model (`docs/research/opencost.md` §4) in FOCUS terms, so cluster rows use it:

| Column | Type | Level | Use on cluster rows |
|---|---|---|---|
| `AllocatedMethodId` | String | Conditional | `LandledgerK8sMaxRequestUsage` (versioned by its details) |
| `AllocatedMethodDetails` | JSON | Recommended | `{"Basis": "max(request, usage) per sample", "Capacity": "node allocatable", "Version": 1}` |
| `AllocatedResourceId` | String | Conditional | The workload and container: `k8s:orbstack/landflow-dev/Deployment/landflow-web/web`; **null on the idle row** |
| `AllocatedResourceName` | String | Conditional | `landflow-dev/landflow-web/web` |
| `AllocatedTags` | JSON | Conditional | The workload's labels, not repeating the node's `Tags` (`allocatedtags.md:16`-`:17`) |

Per cluster, day and resource (CPU, memory), the rows are one per workload container (its allocated quantity × rate)
plus one idle row (capacity − Σ allocated, × rate), all with the node as `ResourceId`. They add up to the node's
capacity × rate. This is **not** Landledger's cost-center allocation: which team, product and P&L class a row belongs to
is in the separate `allocations` table (`specs/003-allocation`), which can split any row, including the idle one, by
rules.

## 4. The columns Landledger drops, and why

| Columns | Why |
|---|---|
| `AvailabilityZone`, `RegionId`, `RegionName` | One local machine; FOCUS allows null when the resource isn't in a distinct region (`regionid.md:13`). Back with a cloud bill (wave 5) |
| `CapacityReservationId`, `CapacityReservationStatus` | No reserved capacity |
| `CommitmentDiscountCategory`, `…Id`, `…Name`, `…Quantity`, `…Status`, `…Type`, `…Unit`, `CommitmentProgramEligibilityDetails` | No commitment discounts on the local cluster or the AI APIs today; they arrive with a cloud bill (wave 5) |
| `ContractApplied` | Contract commitments are wave 3's `contracts` table; the column joins them later |
| `PricingCurrency`, `PricingCurrencyContractedUnitPrice`, `PricingCurrencyEffectiveCost`, `PricingCurrencyListUnitPrice` | Every price is in USD (decision 6); conditional on pricing in another (or a virtual) currency (`pricingcurrency.md`). Return with FX when a provider prices in another currency |
| `InvoiceDetailId` | Wave 3 (the Invoice Detail dataset) |
| `BillingAccountType` | One account type per issuer; nothing to distinguish |

Dropping a conditional column is allowed when its condition never holds; Landledger's documentation lists each
exclusion, which Dataset Completeness asks for (`attributes/dataset_completeness.md:13`-`:14`).

## 5. AI token usage as FOCUS rows

Landflow records each model call with provider, model, operation, input and output tokens, and (in its `ai_usage`
table) cache-read and cache-write tokens, which are **parts of** the input tokens
(`landflow-clickland/apps/web/src/lib/shared/ai-usage.ts:9`-`:15`). Prices differ per part, and a long-context tier
prices a whole request above a threshold at other rates (`landflow-clickland/apps/web/src/lib/server/ai-usage/prices.ts:146`).
So Landledger prices **each call** (the tier is per request), then sums calls into one row per UTC day × provider × model
× workflow × agent × actor × meter × price line.

One day of Claude Sonnet 4.6 in one workflow, 2.4 M plain input, 0.6 M cache-read input and 0.3 M output tokens, at list
prices $3 / $0.30 / $15 per million (rate card v1 takes the providers' list prices, `docs/plan.md` decision 3):

| Column | Input row | Cache-read row | Output row |
|---|---|---|---|
| `ChargeCategory` / `ChargeFrequency` | `Usage` / `Usage-Based` | same | same |
| `ServiceCategory` / `ServiceSubcategory` | `AI and Machine Learning` / `Generative AI` | same | same |
| `ServiceName` / `ServiceProviderName` / `InvoiceIssuerName` | `Claude API` / `Anthropic` / `Anthropic` | same | same |
| `SkuId` | `anthropic:claude-sonnet-4-6` | same | same |
| `SkuMeter` | `Input Tokens` | `Cache Read Tokens` | `Output Tokens` |
| `SkuPriceId` | `anthropic:claude-sonnet-4-6:input` | `…:cache-read` | `…:output` |
| `ConsumedQuantity` / `ConsumedUnit` | `2400000` / `Tokens` | `600000` / `Tokens` | `300000` / `Tokens` |
| `PricingQuantity` / `PricingUnit` | `2.4` / `1000000 Tokens` | `0.6` / `1000000 Tokens` | `0.3` / `1000000 Tokens` |
| `ListUnitPrice` = `ContractedUnitPrice` | `3` | `0.3` | `15` |
| `ListCost` = `ContractedCost` = `EffectiveCost` | `7.2` | `0.18` | `4.5` |
| `BilledCost` | `0` | `0` | `0` |
| `ResourceId` / `ResourceType` | `landflow:workflow:wf_triage` / `Landflow Workflow` | same | same |
| `x_Basis` / `x_Source` | `estimated` / `landflow` | same | same |
| `x_SourceCost` | Landflow's own estimate for the same calls, kept as reported | | |

When the provider's invoice arrives (wave 3), reconciliation appends `invoiced` rows (`BilledCost` = `EffectiveCost` =
the invoice's amount, `InvoiceId` set) and an `Adjustment` row for any difference beyond FOCUS's rounding tolerance,
`MAX(100 × subunit, √rows × 0.5 × subunit)` (`appendix/rounding_variance_tolerance.md:9`). The estimated rows stay; a
report chooses estimated, invoiced, or invoiced-where-available.

## 6. Corrections

FOCUS's three styles (`attributes/correction_handling.md:21`-`:27`); Landledger uses **Ledger**: "reversal of the
original record using a record in which additive metrics … carry values with the opposite sign, while all other columns
match the original; and … a new record with corrected values" (`correction_handling.md:49`). Two cases:

- **Correction inside an open period** (a rate card was applied to the wrong day, a late batch changed a total):
  a reversal row and a re-entry row in the same month. `ChargeClass` stays **null**, because FOCUS reserves
  `Correction` for closed periods (`chargeclass.md:11`-`:14`).
- **Correction to a locked period**: the rows go into the **open** month. `ChargeClass = Correction`, `BillingPeriodStart`
  and `End` are the open month, `ChargePeriodStart` and `End` stay on the original day "to preserve the historical
  accuracy of when the cost was incurred" (`appendix/correction_handling_examples/closed_billing_period.md:11`). FOCUS's
  own example moves part of a charge from one resource to another with a negation and two corrected rows
  (`specification/data/correction-handling-examples/closed-billing-period/scenario_1_partial_reallocation_ledger.csv`).

Landledger's version of that example: October is locked; on 3 November Clickland's late data adds 1.25 core-hours to
`landflow-web` on 30 October.

| Column | Value |
|---|---|
| `ChargeCategory` / `ChargeClass` | `Usage` / `Correction` |
| `ChargePeriodStart` → `End` | `2026-10-30T00:00:00Z` → `2026-10-31T00:00:00Z` |
| `BillingPeriodStart` → `End` | `2026-11-01T00:00:00Z` → `2026-12-01T00:00:00Z` |
| `ConsumedQuantity` / `PricingQuantity` | `1.25` / `1.25` (`Core-Hours`) |
| `ContractedUnitPrice` / `EffectiveCost` | `0.034` / `0.0425` |
| `x_RateCardVersion` | the version effective on 30 October, not today's |
| `x_CorrectionOfId` | null (a late addition reverses nothing); set on a reversal row to the row it reverses |

A correction never edits or deletes a row; locked months' sums never change; the open month shows the correction as
its own line, and Explore can show it against the day it belongs to.

## 7. Custom columns

The rule: "Custom column MUST include the `x_` prefix in the Column ID" (`custom_column_handling.md:23`), Pascal case
after it, alphanumeric, no abbreviations but `Id`, no acronyms but `Sku`, at most 50 characters, `Id` and `Name`
suffixes for identifiers and names (`:24`-`:31`). Numeric custom columns hold one value (`:36`); JSON custom columns
need their schema documented (`:35`). Dataset Completeness asks for columns that correlate a row with the source's own
records and for custom columns to keep source values without rounding (`dataset_completeness.md:15`, `:17`).

Landledger's custom columns:

| Column | Type | Null | Meaning |
|---|---|---|---|
| `x_RecordId` | String | no | The row's own id (a ULID). FOCUS has no row id; corrections and allocations point at it |
| `x_Basis` | String | no | `estimated` (usage × rate card) or `invoiced` (from an invoice). Decides how §2 applies |
| `x_Source` | String | no | `landflow`, `clickland`, `invoice`, `manual` |
| `x_SourceKey` | String | no | The source's identity of what this row counts (e.g. `clickland:2026-11-13:orbstack:landflow-dev/Deployment/landflow-web/web:cpu`); unique per row and basis, so a repeated ingest finds it (spec 002) |
| `x_SourceCost` | Decimal | yes | The source's own cost estimate, unrounded (Landflow's per-call `cost`), so drift between the two shows |
| `x_RateCardVersion` | String | yes | The rate card version that priced the row; null on `invoiced` rows |
| `x_IngestRunId` | String | no | The ingest run that wrote the row |
| `x_CorrectionOfId` | String | yes | On a reversal, the `x_RecordId` it reverses |
| `x_WorkflowId`, `x_AgentId`, `x_ActorId` | String | yes | Landflow's workflow, agent and person or key behind an AI row (rules select on them) |

Two names differ from `docs/architecture.md`: `x_IngestRun` becomes **`x_IngestRunId`** and the record's id is
**`x_RecordId`**, because the `Id` suffix is a SHOULD for identifiers (`custom_column_handling.md:30`). Allocation is not
a custom column: it is the `allocations` table, keyed by `x_RecordId`.

## 8. Periods

The new Billing Period dataset has `BillingPeriodStatus` `Open` or `Closed`, and a closed period goes back to open only
"when explicitly requested or approved by the customer" (`datasets/billing_period/columns/billingperiodstatus.md:13`,
`:19`-`:20`). Landledger's `periods` are `open → closing → locked`; `locked` is FOCUS's `Closed` and is final (reopening is
not offered); `closing` is FOCUS `Open` with ingest still allowed and rule changes frozen.

## Open questions

- `ServiceName` and `SkuId` naming for internal services follow a `landledger:` scheme here; FOCUS asks only that they
  be stable. Finance may prefer plainer names in exports.
- `SubAccountId` for AI rows: the Landflow project is the natural sub account, but `ai.call` events don't carry a
  project today (`landflow-clickland/apps/web/src/lib/shared/brain.ts:86`-`:108` has `projectId` on the event type; the
  `ai.call` writer doesn't set it, `apps/web/src/lib/server/ai-usage/index.ts:174`-`:183`).
